## The setup

The test agent calls `inventory_lookup` before recommending whether a user should place an order. The integration reduces the provider response to an available-unit count:

    if not response.get("available", False):

## The fix

The immediate fix is to reject unknown contracts rather than converting them into zero inventory. The adapter can support both documented versions explicitly:

```python
from typing import Any


class InventoryContractError(ValueError):
    pass


def available_units(response: dict[str, Any]) -> int:
    if "available" in response or "quantity" in response:
        available = response.get("available")
        quantity = response.get("quantity")

        if not isinstance(available, bool):
            raise InventoryContractError("available must be bool")
        if isinstance(quantity, bool) or not isinstance(quantity, int):
            raise InventoryContractError("quantity must be int")

        return quantity if available else 0

    availability = response.get("availability")
    if isinstance(availability, dict):
        state = availability.get("state")
        quantity = availability.get("quantity")

        if state not in {"in_stock", "out_of_stock"}:
            raise InventoryContractError("unknown availability state")
        if isinstance(quantity, bool) or not isinstance(quantity, int):
            raise InventoryContractError("availability.quantity must be int")

        if state == "out_of_stock" and quantity != 0:
            raise InventoryContractError("out_of_stock with nonzero quantity")
        if state == "in_stock" and quantity <= 0:
            raise InventoryContractError("in_stock with nonpositive quantity")

        return quantity

    raise InventoryContractError("unsupported inventory response contract")
```

The important change is the removal of permissive defaults for contract-defining fields. Missing availability data is not confirmed unavailability.

The integration should record `InventoryContractError` as a failed tool outcome. The agent can then retry a compatible endpoint, use a cached value with an explicit staleness warning, or stop the action instead of inventing a stock state.

The regression suite needs fixtures for both contracts, missing data, unknown states, malformed quantities, and contradictory state-and-quantity combinations.

The synthetic check should run at least one known in-stock and one known out-of-stock item. Testing only the empty path would allow this exact false-negative behavior to remain hidden.

## What this argues for

### Missing is not false

Using `.get("available", False)` merges two states: “the provider confirmed unavailable” and “the response did not contain the field.” Those states require different behavior.

### Successful transport is not successful business logic

HTTP 200 proves that bytes arrived. Tool success should mean the response passed the validation required for the agent to use it safely.

### Additive-looking redesigns can be breaking

The new payload added a useful `availability` object, but it also removed two consumed fields. Review diffs from the caller's perspective, not the provider's release-note wording.

### Synthetic checks should exercise decisions

A probe should not stop at status, JSON parsing, or key presence. For high-risk tools, run the same adapter and invariants used by the agent.
