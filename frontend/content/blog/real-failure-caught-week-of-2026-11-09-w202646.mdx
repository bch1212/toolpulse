This post documents a controlled failure drill executed on November 9, 2026 against ToolPulse's current Python shape-fingerprint code. The payloads, counts, fingerprints, and diff below came from that drill, not customer traffic.

The failure is a retrieval API migration that moves `documents[].score` into a nested `relevance` object and changes the score from a number to a string. HTTP remains 200. JSON remains valid. The integration silently removes every relevant document from the model's context.

## The setup

A support agent calls `retrieval_search` before answering policy questions. The adapter keeps documents whose score is at least 0.8:

```python
def selected_ids(response: dict, threshold: float = 0.8) -> list[str]:
    return [
        doc["id"]
        for doc in response.get("documents", [])
        if float(doc.get("score", 0)) >= threshold
    ]
```

The code is permissive. A missing `score` becomes zero instead of becoming a contract error.

The baseline response was:

```json

    {
```

## The fix

The immediate fix is to reject unknown score contracts instead of converting them into zero relevance. During a documented migration window, the adapter can support both forms explicitly:

```python
from typing import Any


class RetrievalContractError(ValueError):
    pass


def read_score(document: dict[str, Any]) -> float:
    if "score" in document:
        raw_score = document["score"]
        if isinstance(raw_score, bool) or not isinstance(raw_score, (int, float)):
            raise RetrievalContractError("score must be numeric")
        return float(raw_score)

    relevance = document.get("relevance")
    if isinstance(relevance, dict) and "score" in relevance:
        raw_score = relevance["score"]
        if not isinstance(raw_score, (int, float, str)) or isinstance(raw_score, bool):
            raise RetrievalContractError("relevance.score must be numeric text or number")
        try:
            score = float(raw_score)
        except ValueError as exc:
            raise RetrievalContractError("relevance.score is not numeric") from exc

        model = relevance.get("model")
        if model != "reranker-v3":
            raise RetrievalContractError(f"unsupported relevance model: {model!r}")
        return score

    raise RetrievalContractError("missing supported score contract")


def selected_ids(response: dict[str, Any], threshold: float = 0.8) -> list[str]:
    documents = response.get("documents")
    if not isinstance(documents, list):
        raise RetrievalContractError("documents must be a list")

    return [
        document["id"]
        for document in documents
        if read_score(document) >= threshold
    ]
```

The compatibility code does not assume that any nested string should be trusted. It parses the score deliberately and checks the model identifier associated with the new representation. If the provider changes calibration or semantics, the adapter should require a reviewed mapping rather than silently comparing unlike values.

The regression suite needs fixtures for:

- the old numeric `score` contract;
- the new nested string contract;
- missing scores;
- nonnumeric score strings;
- unknown ranking models;
- booleans, `NaN`, and infinite values;
- empty and heterogeneous document lists.

The production definition of tool success should occur after this validation. A response that cannot be normalized safely is a failed retrieval operation even when the remote server returned 200.

## What this argues for

### Missing is not zero

`doc.get("score", 0)` merges “the provider assigned zero relevance” with “the provider did not send the field.” Those states require different behavior.

### Retrieval success is a consumer-level decision

A search service can be available while the application receives no usable evidence. Define success after normalization and contract validation, not at the HTTP boundary.

### Eval fixtures can hide live drift

A frozen evaluation response containing `score` continues to pass after the live API moves the field. Keep offline evals, but add canaries that cross the current provider and adapter boundaries.

### Structural and semantic checks complement each other

The fingerprint detects the moved field. A semantic assertion verifies that a known policy query still selects `doc-17`. Either signal alone is less complete.

### Reliability claims need provenance

This was a controlled, reproducible drill using current code, not an invented customer incident. The evidence standard for reliability content should match the standard expected from the monitoring product itself.
