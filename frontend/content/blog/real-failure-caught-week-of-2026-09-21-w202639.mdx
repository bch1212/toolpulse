## The setup

The reconstructed agent has one external dependency, exposed internally as `external_search`. The tool accepts a query and returns ranked records:

```json
{
  "results": [
    {
      "id": "doc_184",
      "score": 0.87,
      "title": "Retry budgets for tool calls"
    }
  ],
  "request_id": "req_92d1"
}
```

The agent filters out results below `0.65`, sorts the remaining records by `score`, and gives the top three titles to the model. The tool is wrapped with ToolPulse, which records duration, success, and a value-free response-shape fingerprint. A scheduled probe runs every 15 minutes with a fixed query whose content is safe to log.

The availability check is deliberately weak: receive a response within 2 seconds and find a non-empty `results` array. The structural baseline is stronger: each result should include string `id`, numeric `score`, and string `title`.

This is the kind of change that looks harmless in a browser and is dangerous at a typed or arithmetic boundary.

## What broke

The agent’s filtering code compares the returned score with a floating-point threshold:

```python
qualified = [
    item for item in response["results"]
    if item["score"] >= 0.65
]
```

In Python, comparing a string with a float raises `TypeError`. In a loosely validated JavaScript path, later sorting or arithmetic may coerce the value and fail less visibly. Either way, the response is structurally incompatible with the assumption encoded by the caller.

The direct failure is easy to repair. The secondary behavior is worse: the orchestration layer retries the complete tool call twice before returning a generic “search unavailable” answer. One malformed response therefore becomes three upstream requests and roughly 700 ms of avoidable work before model time is counted.

If the exception is swallowed and the agent continues with an empty result set, the visible symptom changes from an error to a low-quality answer. Success-rate monitoring at the HTTP boundary still reports 100 percent.

## The fix

The immediate mitigation is defensive parsing at the integration boundary:

```python
from decimal import Decimal, InvalidOperation


def normalize_score(value: object) -> float:
    if isinstance(value, bool):
        raise ValueError("boolean is not a score")
    if isinstance(value, (int, float)):
        return float(value)
    if isinstance(value, str):
        try:
            return float(Decimal(value))
        except InvalidOperation as exc:
            raise ValueError("invalid score string") from exc
    raise ValueError(f"unsupported score type: {type(value).__name__}")
```

The adapter accepts numeric strings temporarily, emits a counter for coercions, and rejects values outside the expected range of zero through one. The team also pins a contract fixture in CI for both the original numeric response and the temporary compatibility path.

The upstream owner is asked to restore numeric JSON encoding. The new string shape is not promoted to the permanent baseline merely because it appeared. Baseline approval happens only after the consumer contract and upstream intent agree.

In this reconstruction, the probe detects drift at 02:15, the adapter is ready at 02:31, and the upstream serializer is reverted at 02:44. Time from detection to compatibility patch is 16 minutes; time to upstream restoration is 29 minutes.

## What this argues for

First, status codes are not contracts. The most damaging agent-tool failures can arrive in fast, successful responses.

Second, synthetic calls matter when traffic is sparse or concentrated. A production-only monitor detects the first affected user. A scheduled probe can detect the dependency change between traffic windows.

Third, automatic baseline promotion should be conservative. Learning every observed shape without review converts drift detection into drift acceptance. Added optional fields may be safe to learn automatically; removed fields, type changes, and container changes usually are not.

Fourth, alert text should name the changed path and type. Engineers can act on `results[].score: number -> string`. They cannot act quickly on “fingerprint mismatch” without another investigation step.
